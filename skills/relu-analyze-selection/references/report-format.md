# 선택 구간 분석 보고서 형식

사용자가 정식 보고서, 원인 분석 또는 비교 요약을 원할 때 이 형식을 사용한다. 값이 없는 항목은 만들지 말고 생략하거나 `확인되지 않음`으로 표시한다.

## 대상

- 서비스와 opaque session/resource 또는 trace 식별자
- 분석한 선택 시작·끝, timebase와 revision
- 적용된 filter, REF/DUT role 등 결과 해석에 필요한 조건
- 사용자의 질문

## 결론 요약

가장 중요한 결론을 1~3개로 제시한다. 각 결론에 `높음`, `중간`, `낮음` 확신도를 붙이고, 단정할 수 없으면 그 이유를 한 문장으로 적는다.

## 관찰된 사실

도구 결과로 직접 확인된 사실만 쓴다. 각 항목에 다음 중 필요한 근거를 붙인다.

- 시간 또는 선택 내 위치
- 사용한 Capability/query의 의미
- 수치, 단위, 표본 수 또는 짧은 원문 발췌
- truncation, sampling, filter 등 범위 제한

도구가 반환하지 않은 값이나 차트에서 육안으로 보았다고 가정한 값을 만들지 않는다.

## 가능한 원인

가능성이 높은 순서로 가설을 정리한다. 가설별로 지지 근거, 반대 근거/대안 설명, 확신도를 분리한다. 시간적 상관관계만 있으면 인과관계로 표현하지 않는다.

## 데이터 한계

revision 변경, 잘림, 수집 공백, clock mismatch, filter, downsampling, 누락된 metric 또는 불충분한 표본을 명시한다. `조회 결과 없음`을 `사건 없음`으로 바꾸어 쓰지 않는다.

## 다음 확인

결론을 실제로 바꿀 수 있는 최소 후속 조사만 제안한다. 필요한 live Capability와 확인하려는 가설을 함께 적는다. UI 변경이나 annotation이 필요하면 실행 전 사용자 승인이 필요함을 밝힌다.
